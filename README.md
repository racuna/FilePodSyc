# FilePodSync (FPS) Specification v1.0

**FilePodSync** is a lightweight, cloud-provider-agnostic podcast synchronization standard. It replaces centralized servers with a file-based approach that works seamlessly with Dropbox, Google Drive, Syncthing, Filen, Nextcloud, or any service capable of folder sync.

## 🎯 Goals
- **Zero-Server Architecture**: Sync relies on your existing file-sync provider.
- **Simple Deployment**: Just share a folder. Read/Write permissions only.
- **Deterministic Merging**: Last-Write-Wins (LWW) at the record level, fully deterministic.
- **Cross-Platform**: Language-agnostic JSON schemas. Works on Android, iOS, Desktop, CLI, Web.
- **Extensible**: Optional tags, robust episode IDs, queue sync, dead-feed detection, snapshots, and logs.
- **Graceful Degradation**: Partial implementations supported (e.g., sync only feeds & episode states).

## 📁 Directory Structure
```
/fps-sync/
├── config.json          # Schema version, sync settings, capabilities
├── devices.json         # Registered device IDs & metadata
├── feeds.json           # Subscriptions & feed metadata
├── episodes.json        # Episode playback states
├── queue.json           # Playback queue (ordered)
├── tags.json            # Optional: user-defined tags (extensible)
├── logs/                # Append-only sync logs (rotated)
│   └── sync-YYYYMMDD.jsonl
└── snapshots/           # Optional: compressed full-state backups
    └── snapshot-YYYYMMDDTHHmmssZ.json.gz
```

## 🔄 Sync Flow
1. **Trigger**: Client opens, closes, pauses, or hits periodic interval.
2. **Fetch**: Download remote JSON files. Compare local & remote `updated_at`.
3. **Merge**: Apply LWW at the record level. Keep the newest change per item.
4. **Apply Local**: Replay pending local operations (add/remove/play/pause/queue).
5. **Upload**: Write merged state back to the folder.
6. **Housekeeping**: Rotate logs, prune old snapshots, ignore `.sync-conflict` files.

## ⚖️ Conflict Resolution
- **Last-Write-Wins (LWW)**: Each record carries `updated_at` (UTC milliseconds) and `updated_by` (UUID v4).
- **Tie-Breaker**: If `updated_at` matches exactly, the lexicographically higher `updated_by` wins.
- **Idempotency**: All operations are safe to reapply. Duplicate additions are ignored.
- **Queue**: LWW applies to the entire file. Clients may optionally implement union-merge for non-conflicting items.
- **New Device**: If remote state exists, local state merges via LWW. Unions feeds, keeps latest episode states.

## 🛡️ Concurrency & Reliability
- **Monotonic Clocks**: Clients should use NTP-synced system time. If unavailable, fallback to device-local monotonic counters.
- **Conflict Files**: Ignore or auto-delete `*sync-conflict*` or `*conflict-copy*` files generated by providers.
- **Rotation**: Logs rotate every 30 days or 10MB. Snapshots retain last 5.
- **Dead Feed Detection**: Syncs `last_check`, `error_count`, and `health_status`. Clients independently flag dead feeds but share the status for UI consistency.
- **Archiving vs Deletion**: `status` can be `active`, `archived`, or `deleted`. LWW applies. Deletion overrides archiving by default.

## 🧩 Extensibility
- **Custom Fields**: `custom` object in feeds/episodes for client-specific metadata.
- **Tags**: Optional `tags.json` with namespace-scoped keys (e.g., `com.myclient:fav`, `com.myclient:skip`).
- **Robust IDs**: `id = guid || sha256(url)`. Ensures cross-client episode matching.
- **OPML Export**: Auto-generated on-demand from `feeds.json`.
- **Capability Negotiation**: `config.json` declares supported features. Clients gracefully degrade.

## 🚀 Getting Started
1. Create an empty folder in your sync provider.
2. Configure your podcast client to point to it.
3. On first launch, the client generates initial `config.json`, `devices.json`, and empty state files.
4. Add more devices pointing to the same folder. They auto-merge.
